# H9 bounded-loading and calendar oracles

## Data and selection

1. At1000 active clients, bootstrap has1000 compact identities and remote:false. Adding one active client changes the next directory to remote:true, totalCount1001 and zero identities. Search for a unique client returns exactly that identity; no contact fields. Frontend save patching crosses the same boundary without replacing existing identities with page1.
2. Jobs page1 limit20 has <=20 latest family rows. Page999 may be empty but retains the total. Ascending/descending ID ordering changes the first result. One client with20595 historical rows still receives <=100 current choices. Business scope includes shared jobs, excludes another business and refuses foreign entities.
3. A late reply for clientA cannot overwrite choices after switching to clientB. Selected job resets on client/business change; selected historical ID is hydrated directly if absent from the first choices. A missing/failed lookup displays a retryable error, not an apparently complete empty directory.
4. Create/edit/delete returns changed records/IDs independently of their first-page position. Each affected page has <=20 rows, pagination and partial:true; no grid/tree duplicates or account-wide jobs. Paginated reads never overwrite shared reference state. Committed refresh failure says saved/reload/do-not-resubmit and still represents exactly one write.
5. Linked work/write-offs/payments on any job version prevent deleting its family. The UI receives counts and bounded previews, not only whatever happened to be in bootstrap page1. Backend locks/refusals remain authoritative.

## Money preservation

Existing hand-computed lifecycle suites still prove payments before/after invoicing, retainers, invoices, carried balances, corrections, refunds, two businesses and zero drift. H9 changes delivery rather than amount formulas. A compact-response lifecycle adds a40 charge, finalizes40, records10 retainer credit, receives5 against the invoice, and enters2 unbilled write-off: billed due35, available retainer-10, next invoice33. The held10 remains separately available until explicitly applied; subtracting it again would incorrectly report23. Each of the six create families returns only changed records plus bounded pages. The snapshot-date regression has a separate oracle: a Sept26 invoice with300 due and a child balance120 recorded at Sept27 01:00 UTC (Sept26 18:00 Phoenix) has **120 due** as of Sept26 when knowledge reaches02:00 UTC. A Sept25 as-of or knowledge before the child still sees **300**. `test/endpoints/payments/H9-evening-aging.spec.js` fixes both boundaries explicitly.

## Current-cycle picker oracle

A job root has $10 already billed. A later job version has $40 billable unbilled work, $12 nonbillable work and $8 retainer-funded work in business A. The shared root also has $33 unbilled work in business B. The A picker shows the root at $0 and the later version at **$40**; B shows the shared root at **$33**. It must never display the family lifetime total or another business's work. Search by exact ID and limit 1 preserve the chosen identity. Invoice-only reads expose only the chosen client's/business's snapshots. Malformed projection options, wrong account/client, insufficient role and database failure preserve every row. Browser coverage injects a job read failure, retries through type-ahead, selects the $22.50 synthetic current-cycle job and records a $2 job-linked write-off without an invoice link. Existing invoice-linked payment/write-off/reversal flows still run unchanged.

Retainer-only and payment-only profile projections each return only the requested client history; absent/foreign clients, role/tenant rejection and injected query failures leave all rows unchanged. Payment record hydration joins exact reference IDs locally, without a jobs list. Retainer deletion still checks all linked payments, not a grid page.

Picker-reset oracle: type a job term for client A, choose client B, then return to A without typing. Both the visible input and outgoing search must be empty after each switch. Changing business also clears the term. Jest exercises the shared scope reset and current-cycle picker; the real-data browser lookup test asserts the new client request contains an empty search.

Inline-review transfer oracle: client A has one unbilled $22.50 time entry; client B has none. A failed remote client search, selecting B without its job, and a failed save each leave A=$22.50 and B=$0 with identical financial rows. Selecting B’s business-scoped job and retrying the existing update moves that one entry to B: A=$0, B=$22.50, the business and amount remain unchanged, and no new payment/invoice appears. `billing-review-H9.spec.js` exercises this through real fixture-9001 reads/writes with only the large-directory mode and explicit failures intercepted.
