# Pass 3 expectations, recorded before new tests

Specification: the feature guides under `ledger/`, `work/`, `invoicing/` and `platform/`, with the 2026-09-25 owner confirmation taking precedence. Existing literal financial oracles in scenarios 01–18 and the what-if catalogue remain the oracle for those tests.

1. Every mounted authenticated route refuses an absent session with HTTP 401 and the documented missing-token envelope. Expired, malformed, inactive and unknown identities cannot write. An account URL differing from the verified session refuses 403 before row access. A lower role cannot use a privileged route. A staff user cannot read or mutate another employee's private resources. Body account/actor values cannot override the session.
2. A valid create/read/update/delete affects only its selected tenant and records. A missing/foreign row produces the handler's documented not-found response (or an empty collection for collection-shaped legacy reads). A dependency, lock, invalid related ID, invalid scalar/date/amount or invalid state produces its documented refusal. Assertions compare all scenario database tables, including audit metadata, before and after refused requests; consumed sequence numbers are not committed business writes.
3. A precommit database/storage failure produces the documented failure envelope and preserves database rows. A failure fetching a grid after a committed mutation must report success with a reload warning, preventing a duplicate retry. An unavailable optional logo or narrative may degrade gracefully. Uploads/immutable printing may leave only the explicitly documented unreferenced unique local object after a metadata failure; they may not publish a successful record or alter financial rows.
4. Drafts stay editable and write nothing to the ledger. Finalize is sent and locks its invoice and statement members. Editing/deleting/reassigning a sent member refuses HTTP 409, `code: SENT_INVOICE_LOCKED`. No role or request field bypasses this. A bounced-check exception permits only its selected once-only reversal, followed by revision/reprint or roll-forward. Original invoice/PDF and history remain immutable.
5. Literal ledger checks: $100 work minus a $25 receipt = $75 debt. A $50 retainer receipt creates $50 available funds and zero debt; a $20 refund leaves $30 funds and still zero debt. Flagging/dismissing a duplicate changes neither amount; removing an unissued $10 duplicate reduces work by exactly $10. $100 work minus $150 receipt = -$50 credit; default finalization skips it without writes, explicit credit selection issues -$50 and locks it. Six-minute time increments remain unchanged.
6. Audit Record is Admin/Super Admin only, within the session tenant. Ordinary history reads write nothing. Printing creates a new immutable record (201); reopening returns exact stored bytes and a nonfinancial reopen action. Invalid filters/IDs/type refuse 400, missing/foreign records 404, failed integrity 409, database/render/storage failure 500. Failed requests publish no metadata or financial writes. Forged evidence/PDF identities, byte counts, digests, chain anchors and direct audit mutation cannot succeed.
7. The route inventory includes both health mounts, auth endpoints, the retired AI integration catch-all, and all owner-decision routes. An early mandatory guard can make a later defensive check unreachable from HTTP; the matrix must name that guard and evidence instead of claiming the later branch was exercised.

Transport status and JSON status are asserted separately. Existing legacy HTTP-200/JSON-500 refusals are characterized explicitly, not mistaken for success. Unexpected differences are defects or documented expectation corrections; assertions are not relaxed merely to obtain a green run.

Execution evidence and exact route/test-name mappings will be recorded in `path-matrix.md` and `RESULTS-PASS3.md`.

## Report and archive fault oracles (before tests 08–09)

An audit batch is an explicitly requested report write. A customer query failure may record one failed audit result; if that error-record write also fails, the job must still finish with a failed result and no database changes. An optional app-balance query failure leaves a completed audit with a null app comparison and the error recorded. An unavailable PDF store leaves a completed numerical audit with no published PDF key. These outcomes do not alter money. A stored PDF read failure may rebuild the report; malformed persisted report data must return a JSON 500, never JSON mislabeled as PDF. A ZIP failure before streaming must return JSON 500; after bytes have been sent it must terminate the stream, never hang or claim a complete ZIP.

Additional unissued legacy invoice guards must refuse linked activity and historical balance rows even when no sent artifact exists. A response-list failure after an allowed empty invoice deletion must report the already committed deletion. A failed related duplicate-review update must roll back the source deletion and all related review/audit writes. A revision archive with zero or two customer PDFs must refuse the revision and leave original evidence and money untouched.

Expectation correction: tracker upload deliberately uses a fixed generic 500 message for an unexpected pre-validation database failure. The first test expected the injected diagnostic text. The assertion now checks the documented generic message, HTTP 500 and the same full database no-write invariant; no application change was needed.

## Response decoration and final defensive checks (before tests 14–16)

A lock/duplicate-status lookup happens after the application builds a response. If a write already committed, failure of this lookup must still confirm success and advise a reload without exposing undecorated editable rows. The hand ledger is $100 existing work plus one $10 charge = $110, followed by one finalized/sent $110 invoice, one immutable issue and one original revision. A read-only lookup failure returns 500 and changes no rows. A later fault test extends this oracle to a partial batch: preserve its archive download, skipped-customer identities and newly committed invoice IDs while omitting rows whose lock state could not be loaded; finalize the other customer at exactly $50 once. The first implementation dropped this response metadata, and failing assertions preceded the correction.

A missing row discovered by a second locked lookup must refuse without writes. Invalid configured billing timezone may fall back to the local calendar date; it must not mutate the ledger. Failure of an optional inference audit store, workbook repair, worksheet protection or training lookup must follow the documented fallback and never invent work or alter money. A failed mandatory workbook rebuild must never return another tenant's template.

Expectation corrections: the reviewer-note sanitizer's shared Comprehend helper catches service failures itself and performs deterministic redaction. The first test incorrectly expected null from an outer defensive catch. Its corrected fixture contains an email and asserts the exact replacement `Contact [REDACTED_EMAIL]`, null original training notes, and the successful requested ledger edit. A transaction disappearing/changing owner during save retains the existing HTTP-200/JSON-500 legacy envelope; both statuses, its specific refusal message and full no-write snapshot are now asserted. Background ingestion accepts work with 202, and an invoice preview renders a PDF only when the draft option is selected. Those test inputs/expectations were corrected; the business rules were not changed.

## Local screen oracles (before the browser pass)

The existing local fixture employee bills $75/hour: 0.3 hours is exactly 18 minutes and $22.50. CSV/draft generation leaves invoice rows and audit postings unchanged; finalize creates one $22.50 sent/locked invoice. An empty exception selection cannot be submitted. A new $25 retainer followed by a $5 refund leaves $20 available and does not change the $22.50 invoice debt; a $26 refund is refused before submission. A duplicate flag on a sent charge does not change its amount and cannot enable removal. Audit printing/reopening preserves financial rows and reopening returns the identical downloaded bytes; reversed dates refuse locally and an employee cannot reach Audit Record. These browser writes are confined to fixture account 9001 in ds2_local. Immutable local evidence is retained, not forcibly deleted.

## Existing form response messages (before the final message fault check)

Several existing CRUD forms display only the response `message`. Therefore a committed refresh failure must include the saved/reload/do-not-resubmit guidance in that message as well as the structured `warnings` array. Creating or editing a job category/type must never say it was deleted, and updating/deleting a job must not say it was newly created; a shared create/update/delete response can accurately say that its changes were saved. These are response presentation rules, with no change to the committed write or invoice arithmetic.
